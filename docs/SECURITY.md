# Security Model

## Absolute rule: NO RAW WRITES, EVER

The harness performs **zero raw hardware writes**:

- No MSR write (`wrmsr`), no `setpci -w`, no `/dev/mem` write, no firmware/BIOS
  flash, no SMBIOS write. `force_read_only: true` applies to the entire runtime.
- `setpci` only with read flags; `/dev/mem` is not a capability anywhere.
- No `dd`, `mkfs`, `shutdown`, `reboot`, `flashrom` in the allowed command set.
- Writes appear **only** as recommendations in `diagnosis.json`, pending human
  approval. The only writers on the system are (a) a human with physical/console
  access, or (b) a separate independently-audited automation layer.

## Enforced invariants (code, not convention)

1. **Single choke point** — `inspect`/`plan` only invoke commands via
   `engine.runner`. Every argv is validated against the **exact argv-template
   allowlist** (`engine/allowlist.py`) and must be read-only.
2. **No shell interpolation** — commands run parameterized
   (`subprocess.run([...], shell=False)`); `*`, `|`, `;`, `$(...)`, backticks
   never reach a shell.
3. **No inline secrets** — inventory stores vault paths only; `harness lint`
   rejects inline credentials. Sudoers is generated by
   `engine/sudoers_gen.py` and is read-only after deployment; drift is flagged.
4. **Credentials never reach the LLM** — registration is a non-agent CLI
   (`harness secrets`), key material accepted as a **file path** only; passwords
   read via `getpass`, never echoed. Prompts/transcripts/audit carry vault paths.
5. **Console path is trust-gated** — `SerialConsole` refuses to construct unless
   `trust_level` is `lab`/`qa`; `validate_serial_probe` rejects destructive or
   injection-y commands; host keys are pinned (a key change raises and stops).
6. **Audit trail** — append-only, hash-chained `audit.jsonl` with secret
   redaction; every run reproducible from `harness_runs/<id>/`.

## Threat model

| Threat | Mitigation |
|---|---|
| Agent is tricked into a destructive command | Exact argv allowlist + `force_read_only`; write verbs absent from the catalog |
| Prompt injection exfiltrates credentials | Credentials live only in the secret store; prompt holds vault paths |
| Shell injection via target names (rack/cable/IP) | `validate_identifier` rejects `;`, `$()`, backticks, etc. |
| Rogue rack manager / MITM | Host keys pinned in `known_hosts`; change ⇒ hard stop |
| Secret leakage into logs | `audit/redact.py` scrubs key material from all logs/transcripts |
| Console abuse at prod | `trust_level=prod` blocks the entire console path |

## Operational notes

- Keep `keys/` and `secrets/` out of version control (see `.gitignore`); they
  are git-ignored.
- Rotate SSH (OS diagbot) and BMC/IPMI credentials separately; the inventory
  models them as distinct domains.
- Run with `--approval` (or `--approve-all`) so every recommended action is
  explicitly recorded; `harness verify --baseline <dumps.json>` confirms an
  error counter moved before/after a repair.
