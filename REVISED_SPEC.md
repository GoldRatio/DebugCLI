# Agent Harness — Revised Spec

> Rev 2.0 — resolves the **access/privilege policy** contradiction and defines the
> **module layout**. Supersedes the original one-screen spec where they conflict.

---

## 1. Access & Privilege Policy (resolves the contradiction)

### 1.1 Absolute rule: NO RAW WRITES, EVER

The original spec allowed a "command allowlist," `setpci -w`, `/dev/mem`, and
described a "security wrapper that prevents writes unless approved." That framing
is wrong because it implies writes are conditionally permitted. The revised rule
is unconditional:

> **The harness performs zero raw hardware writes. No MSR write, no `setpci -w`,
> no `/dev/mem` write, no firmware/BIOS flash, no SMBIOS write. Ever.**
> `force_read_only: true` is applied to the entire agent runtime.

Writes of any kind are **output only** as recommendations in the diagnosis JSON.
The only writers on the system are: (a) a human with physical/console access, or
(b) a separate, independently-audited automation layer that is *not* part of this
harness.

Consequences of this rule:

- `setpci` may only be used **with a `-r`/read flag** (never the write form).
- `/dev/mem` is **rejected outright** as a capability. MMIO reads use vendor tools
  (`ipmitool`, `racadm`, `hpe-restful`) or `/sys`/`sysfs` files instead.
- No `dd`, `mkfs`, `shutdown`, `reboot`, `flashrom`, `nproc`-writes anywhere in the
  allowed command set.
- No `sudo` grant is ever issued for a command that could write hardware; the
  sudoers file is generated by the harness bootstrap and is itself read-only after
  deployment.

### 1.2 Allowlist is exact (program name + pinned safe args)

Binary names alone are insufficient (e.g., `smartctl` reads but also has write
flags). The allowlist is a set of **exact argv templates**. Sudo is granted only
to templates matching a safe form, e.g. sudoers:

```
diagbot ALL=(ALL) NOPASSWD: /bin/smartctl -a /dev/*
diagbot ALL=(ALL) NOPASSWD: /bin/smartctl -x /dev/*
diagbot ALL=(ALL) NOPASSWD: /usr/sbin/ipmitool sensor \
diagbot ALL=(ALL) NOPASSWD: /usr/bin/rdmsr -a -p *
diagbot ALL=(ALL) NOPASSWD: /sbin/modprobe msr \
```

Rules:
- Each template pins the read-only flags. Any other flag set → **denied**.
- Arguments are passed parameterized (`subprocess.run([...], shell=False)`); never
  shell-interpolated. No `*`, `|`, `;`, `$(`, backticks reach a shell.
- The sudo file is generated, hashed, and the hash recorded; drift is flagged.

### 1.3 Two credential domains (previously conflated)

SSH (OS-level diagbot) and BMC/IPMI must use **separate, rotated credentials**:

| Domain | Auth | Rights |
|---|---|---|
| OS over SSH | key-based only, ephemeral from vault, host-key pinned | `diagbot` user = exact read-only allowlist |
| BMC/IPMI | rotated user over LAN (HTTPS/IPMI), never the OS key | read-only sensor/SEI/FRU/RACADM queries |

Inventory stores **vault paths**, never inline secrets. An inventory lint rule
rejects any YAML containing a literal credential.

### 1.4 Trust levels gate execution, not reads

Reads are allowed everywhere. The *only* thing trust level changes is whether the
harness may auto-propose vs. only report, and whether it enables SOL fallback:

| trust_level | Reads | Auto-propose actions | SOL fallback |
|---|---|---|---|
| `lab` | yes | yes (gated by 3-stage validation) | yes |
| `qa` | yes | human approval only | yes |
| `prod` | yes | human approval only; alerts on host-key change | no (alert + stop) |

`/dev/mem` write and destructive commands are **blocked at every level**.

## 2. Module Layout

Monorepo, Python 3.11+. Modules are reverse-dependency ordered: low-level primitives
(H) depend on nothing; high-level (A) depend on all lower.

```
harness/
  pyproject.toml                 # single package "harness"
  README.md

  # ---- I. Secure SSH & Command Execution Engine ----
  engine/
    session.py                   # connection lifecycle, host-key pinning, alert-on-change
    runner.py                    # param subprocess / ssh exec; captures out/err/exit/timing;
                                 #   ENFORCES allowlist + force_read_only (single choke point)
    allowlist.py                 # loads & enforces exact argv templates; denies non-conforming
    security_gate.py             # validator consulted BY runner; used by tests/audit; not bypassable
    retry.py                     # retry policy + idempotent-command registry (flaky-network handling)
    sudoers_gen.py               # generates + hashes sudoers file at bootstrap; read-only after
    bastion.py                   # SSH proxy/bastion hop support
    sol.py                       # serial-over-LAN fallback (trustlab/qa only)

  # ---- II. Register & Sensor Inspection Library ----
  #   Owns the CURATED register catalog + decoder (docs only ingests/retrieves the raw PDFs)
  inspect/
    model.py                     # dmidecode-based model detection -> picks collector profile
    base.py                      # ICollector interface: collect()->RegisterDump
    collectors/
      cpu_msr.py                 # rdmsr/turbostat/cpuid
      pcie.py                    # lspci -xxx / sysfs config (read-only)
      ipmi.py                    # ipmitool sensor/sel/fru via BMC cred domain
      kernel.py                  # dmesg, /proc/sysrq, pstore, crash
      storage.py                 # smartctl -a/-x, nvme, storcli (read-only forms)
    decoder.py                   # raw_hex -> RegisterDecode using curated catalog
    catalog/
      register_catalog.yaml      # CURATED register defs (versioned, reviewed, signed-off)
      catalog_loader.py          # version + sign-off checks; authoritative over PDF

  # ---- III. Document Ingestion & Retrieval ----
  docs/
    ingest/
      pdf_parser.py              # pymupdf layout-aware parse (+OCR hook for scanned)
      table_extract.py           # register tables -> structured JSON/YAML (fallback to catalog)
      embed.py                   # 500-token chunks, 100-token overlap -> vector store
    retrieval/
      hybrid_search.py           # BM25 + semantic (dense) fused
      rag.py                     # top-k section retrieval w/ page citations
    parts/
      parts_graph.py             # parts list -> slot->FRU/PN/SN graph (no inspect dependency)

  # ---- IIb. Collection Planning ----
  #   Maps initial symptom -> subsystem -> minimal targetted collector set (fixes:
  #   diagnosis.engine was over-loaded && we were collecting everything up front)
  plan/
    subsystem.py                 # initial symptom/error counters -> likely subsystem(s)
    profile.py                   # subsystem -> ordered minimal collector set

  # ---- IV. Diagnostic / Reasoning Engine ----
  diagnosis/
    schema.py                    # Pydantic: RegisterDump, RegisterDecode, Diagnosis, Action
                                 #   schemas carry schema_version; migration = optional fields
    summarize.py                 # anomalous-register summarizer (context budget for LLM)
    engine.py                    # orchestrates plan -> collect -> decode -> retrieve -> prompt
    parts_validate.py            # adapter: docs.parts_graph <-> inspect.ipmi snapshot (FRU checks)
    prompt.py                    # strict system/user prompt (no-write rule, citation-enforced)
    scorer.py                    # confidence scoring (see scoring definition)
    verifier.py                  # post-action feedback loop: re-run, compare counters, close ticket

  # ---- V. Audit, Logging & Trust ----
  audit/
    auditlog.py                  # append-only + hash-chained trace (WORM backend)
    redact.py                    # scrub secrets before storage
    trace.py                     # session_id linking summary <-> full cmd trace <-> raw log

  # ---- VI. Operator Interface & Orchestration ----
  operator/
    cli.py                       # CLI + interactive approval gate
    tickets.py                   # action list -> ticketing/UI for human approval
    supervisor.py                # per-step timeouts, infinite-loop detection, escalation

  # ---- VII. Config & Secrets ----
  config/
    inventory.yaml               # hosts; contains VAULT PATHS only, no secrets
    inventory_lint.py            # rejects inline credentials
    vault.py                     # secrets-manager client (Vault / AWS SM)

  tests/
    unit/
      test_allowlist.py
      test_decoder.py
      test_scorer.py
      test_sudoers_gen.py
      test_parts_graph.py
      test_security_gate.py
    integration/
      test_hybrid_search.py
    fixtures/
      sample_register_map.pdf
      sample_parts_list.xlsx
```

### Dependency order
```
(H) config, audit            -> no deps
(G) engine, inspect.base     -> config, audit
(F) inspect.catalog, decoder -> inspect.base
(E) inspect.collectors, plan -> engine (read-only runner), inspect.base, inspect.catalog
(D) docs.ingest              -> config
(C) docs.retrieval, docs.parts -> docs.ingest      (docs does NOT depend on inspect)
(B) diagnosis.engine         -> plan, inspect.*, docs.*, diagnosis.schema, engine
(A) diagnosis + operator     -> B + audit + config
```

### Data flow (one run)
```
inventory -> engine.session (open, host-key check)
          -> plan.subsystem (classify initial symptom -> subsystem(s))
          -> plan.profile (subsystem -> minimal collector set)
          -> inspect.collectors[*] (via read-only runner) -> RegisterDump
          -> inspect.decoder -> RegisterDecode[] (from curated catalog)
          -> diagnosis.summarize (anomalous registers only, context budget)
          -> docs.retrieval (hybrid) + diagnosis.parts_validate (FRU cross-check)
          -> prompt -> LLM -> Diagnosis (schema-validated, citations required)
          -> scorer assigns confidence; verifier queues post-action checks
          -> operator.cli/tickets present actions for human approval
          -> audit.auditlog records immutable trace; redact scrubs secrets
```

## 4. Confidence scoring (addressing "explain every step")

`confidence` is a defined fusion, computed in `scorer.py`, output in
`Diagnosis.confidence_breakdown`:

```
score = 0.55 * retrieval_citation_support
      + 0.30 * evidence_fit           # decoded registers directly support diagnosis
      + 0.15 * model_agreement        # model calibration (logprob / calibration set)
- penalty for: firmware/doc mismatch, missing stepping def, low FRU confidence
```

`retrieval_citation_support` = fraction of cited page references that returned
relevance score above threshold and actually appear in the doc chunks retrieved.
This makes the number reproducible and auditable, and forces the model to cite.

## 5. Curated register catalog (highest correctness risk)

`docs/catalog/register_catalog.yaml` is the single source of truth for bit-field
decoding. Requirements:

- **Versioned** (semver), **reviewed/signed-off** per version; owner documented.
- Schema: `{ mnemonic, addr/bus_id, canonical_source, page_ref, version_valid, bits: [{name, msb, lsb, values: [{v, meaning}] }] }`.
- When the PDF table differs from the catalog, the catalog wins and the PDF
  chunk is marked `superseded`. Unknown steppings → flagged, never guessed.
- Adds correct-defense in depth: even if the LLM misreads a register, decoding
  already happened deterministically in `decoder.py`, not by the LLM.
